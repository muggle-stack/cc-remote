# 应用内更新

右上角「⋮ → 检查更新」显示当前页面、服务器和当前设备的版本、稳定版更新内容以及升级进度。
「加粗字体」移至「外观 → 阅读设置」，仍是所有引擎共用的偏好。

此入口更新 cc-remote 的 Web/PWA、Relay 和当前 Wrapper；其他设备单独更新。
Electron 应用本体和 Harmony HAP 仍通过各自安装渠道更新。
首次使用需要先通过既有部署流程安装包含此功能的 Relay/Web/Wrapper。
旧 Relay 或未接入维护通道的设备会显示不可用，不会通过聊天执行更新命令。

## 一次性启用

在设备的独立终端中执行：

```bash
cc-remote ui-updates enable
```

macOS 以原桌面用户运行，使用 LaunchAgent 启动独立升级任务。
Linux 通过安装的管理命令获取管理员授权，安装只允许操作该固定安装目录的专用 helper；
当前要求主机有可用的 systemd。源码运行、非托管安装和没有 systemd 的容器不支持设备端按钮升级。
不会在浏览器中索取或存储 sudo 密码。

如果已经使用 `cc-remote update --relay-ssh …` 配置并验证了管理员 SSH 入口，
可以明确允许当前设备同时更新配对服务器：

```bash
cc-remote ui-updates enable --allow-relay-update
```

该选项复用已有 SSH 授权，不授予新的服务器权限。未启用时，服务器需要升级会阻止设备安装；
服务器已是兼容版本则无需该权限。启用不重启 Wrapper，下一次检查更新即可读取配置。
使用自定义 `CC_REMOTE_STATE_DIR` 时，附加 `--control-socket /absolute/state/control/control.sock`，
必须与当前 Wrapper 的私有控制套接字一致。

禁用后不会再接受新的更新，尚未进入安装的任务会安全取消；已经开始的安装继续完成或回滚：

```bash
cc-remote ui-updates disable
```

## 执行与恢复

- 只接受管理员配置的 GitHub 仓库当前最新稳定版本，不接受命令、下载 URL、环境变量或降级请求。
- 设备先校验安装包，再等待当前会话、权限问答、后台工作和排队消息结束。等待期间仍可使用会话，
  也可取消更新；开始安装后暂停新操作，直到重新连接。不会强行中断模型或接管原生 CLI。
- 更新由独立的 launchd/systemd 任务运行。关闭面板、浏览器断线或 Wrapper 重启不会取消已接受的更新。
  页面重开时查询原任务；启动结果未知时保留原编号，重复点击不会创建第二个 OS 任务。
- 复用既有安装锁、SHA256 校验、不可变版本目录、事务回滚及保留清理。
  普通更新不重启独立 Claude 服务。协议或 Claude SDK/服务契约变化仍要求协调维护，不允许按钮绕过。
- 页面刷新仍检查输入草稿、附件、未保存编辑和待确认操作；有未保存内容时提示处理，不自动丢弃。

策略保存在安装根目录 `ui-update-policy.json`，升级记录在 `ui-update-jobs/`。
Mac 日志是对应任务的私有 `.log`，Linux 日志可按 `cc-remote-ui-update-<id>` 查询 journal。
公开面板只返回阶段和受控原因，不返回本地路径、进程输出、命令或凭据。
完成的 macOS 任务会卸载其 launchd 注册，Linux 临时单元由 systemd 回收；磁盘上的小型记录保留用于去重。
记录上限为 1024，达到上限后拒绝新更新，由管理员核实维护，不删除旧记录来绕过去重。

「结果待确认」意味着启动确认丢失、工作进程无法确认或安装结果需要检查。
服务器更新提交后 SSH 断线、状态查询失败或公共健康检查未通过，也保留这个状态和维护限制；
需先核实 `upstream-update.json` 指向的原服务器事务及线上状态，不会当成权限失败重新提交。
先检查同编号 OS 任务、既有安装事务、`current`、服务健康及连接状态；
不要删除记录、换一个编号重试或假定已经失败。安装已开始但结果未知时会保留维护限制，
需要管理员按部署恢复流程核实后恢复。浏览器不会自动将这种情况标记为成功。

## 通信边界

维护使用独立 schema 1 通道，聊天协议版本不变：

- 浏览器 `/api/updates/{machine_id}` 使用既有登录 Cookie、设备权限及写操作精确 Origin 校验。
- Wrapper `/ws/updates` 使用设备 Bearer 凭据，动态吊销会在请求和响应时重新检查。
- 设备使用现有私有 Unix 控制通道提交安装前的空闲预留；检查与预留之间不挂起。
- 每设备请求数量、帧大小、HTTP 请求体和记录数量有上限。Relay 不保存升级任务状态。

这条通道不提供任意远程管理 shell。升级只能复用设备管理员事先启用的安装和服务器权限。
