# cc-remote v5.3.18

## 中文

优化应用内更新的等待条件，已确认独立运行且可恢复的任务可在更新期间继续执行。

- 不再因为存在运行中的会话就一直等待：已由独立 Claude 服务接管的会话和问答、有完整恢复记录的共享 Codex 回合，以及已连接的 DSH 原生任务，可在 Wrapper 更新期间继续运行。
- 安装前核实任务归属和恢复条件。Wrapper 内执行的任务、私有侧聊、排队消息、提交中的操作、临时附件依赖、Codex／DSH 待回答问题及无法确认归属的活动，仍需等待安全边界。
- 安装期间暂缓 Claude 自动压缩，避免维护开始后产生新的本地操作。普通更新继续保留独立服务，不重启原生引擎或重复提交任务。
- 更新窗口使用「等待安全更新」「就绪后更新」等提示，说明仍在等待哪些操作，不再笼统要求所有任务结束。

通信协议保持 **v90**，Claude Agent SDK 保持 **0.2.174**。本次更新不更换原生引擎版本；协议或 SDK／服务契约变化仍需协调维护。

已启用应用内更新的设备，可从右上角「⋮ → 检查更新」进入并安装。也可使用：

```sh
cc-remote update --check --version 5.3.18
cc-remote update --version 5.3.18
```

首次启用条件见[应用内更新说明](https://github.com/muggle-stack/cc-remote/blob/v5.3.18/docs/in-app-updates.md)。设备需要能够访问 GitHub；已知代理 TLS 失败仍可能被显示为「协议变化」，本次未调整该错误分类。

## English

Allow in-app updates while independently owned, recoverable tasks continue running.

- Stop waiting solely because a session is active. Sessions and questions owned by the independent Claude service, shared Codex turns with complete recovery records, and connected DSH native tasks can continue through a Wrapper update.
- Verify ownership and recovery before installation. Wrapper-owned work, private side conversations, queued messages, in-flight operations, temporary attachments, pending Codex/DSH questions and unconfirmed ownership still require a safe boundary.
- Defer automatic Claude compaction during installation so maintenance does not start new local work. Ordinary updates preserve independent services without restarting native engines or resubmitting tasks.
- Clarify the waiting state and installation action, explaining which operations still need to finish instead of requiring every task to end.

Wire protocol **v90** and Claude Agent SDK **0.2.174** are unchanged. This release does not upgrade native engines; protocol or SDK/service-contract changes still require coordinated maintenance.

On devices with in-app updates enabled, open **⋮ → Check for updates** to install, or run:

```sh
cc-remote update --check --version 5.3.18
cc-remote update --version 5.3.18
```

See the [in-app update guide](https://github.com/muggle-stack/cc-remote/blob/v5.3.18/docs/in-app-updates.md) for first-time setup. Devices need GitHub connectivity; the existing misclassification of some proxy TLS failures as a protocol change remains unchanged.
