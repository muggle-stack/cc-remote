# cc-remote v4.0.7

## 中文

v4.0.7 新增按模型选择 Codex 速度，修复 Claude 会话恢复、临时侧聊清理和
代理连接。产品版本 **4.0.7**，通信协议升级为 **v73**，Claude Agent SDK
保持 **0.2.157**。

### 本次更新

- **Codex 速度**：从当前账号的原生模型列表读取可用档位，在 Code、Work 和侧聊
  中显示模型对应的速度选择。保留原生档位，切换模型时清除不支持的选择；
  Ultrafast 仅在上游为该账号和模型提供时显示。
- **Claude 恢复**：独立服务中尚未产生转录文件的预热会话可重新连接；启动时
  复用已恢复的默认账号会话，避免反复创建空闲工作进程。不重发已接受的消息。
- **侧聊清理**：清理后保留私有会话身份记录，防止原生进程延迟写入让已关闭的
  侧聊重新出现在普通列表中；确认只有元数据的条目不再作为对话展示。
- **跳到底部**：点击按钮立即回到最新消息，长历史不再缓慢滚动到底。
- **代理连接**：Relay 连接采用显式 HTTP 代理环境变量，保留 `NO_PROXY` 规则
  和本机回环直连，避免自动选择失效的系统 SOCKS 代理。

### 升级

**协议从 v72 升至 v73，旧 Wrapper/Web 不能与新 Relay 混用。** 安排同一维护窗口，
先停止不兼容的旧 Wrapper，更新 Relay + Web，再更新并启动全部 Wrapper。
安装器管理的部署在独立终端使用：

```bash
cc-remote update --version 4.0.7 --allow-protocol-change
```

设备更新先核对配对 VPS；已经更新到目标版本时只更新本机。其他设备仍需逐一更新，
完成后重新加载 Web/PWA。源码和容器部署保留原有流程，见
[安装与升级](https://github.com/muggle-stack/cc-remote/blob/v4.0.7/docs/installation.md)。

Relay 控制连接支持 `HTTPS_PROXY` / `HTTP_PROXY` 及其小写形式和 `NO_PROXY` /
`no_proxy`；仅配置 `ALL_PROXY` 或系统代理的部署需要显式配置 HTTP 代理入口。
这些设置不替代 Claude/Codex 自身的模型连接配置。

从 v4.0.6 升级不需要为本次修复重启独立 Claude 会话服务。更早版本仍需遵循
[Claude 服务迁移指南](https://github.com/muggle-stack/cc-remote/blob/v4.0.7/docs/claude-session-service.md)，
等待原生任务和待处理输入结束。普通 Wrapper 更新保留独立服务及其任务。

本次发布 Web、Relay 和 Claude/Codex Wrapper；不包含实验分支的 DSH 或 Desktop 安装包。

## English

v4.0.7 adds model-specific Codex speed selection and fixes Claude recovery,
private side-chat cleanup and proxy routing. Product version **4.0.7**, wire
protocol **v73**, Claude Agent SDK **0.2.157**.

- **Codex speed:** read available tiers from the current account's native model
  catalog for Code, Work and side chats. Preserve native tier identities and
  clear unsupported selections when changing models. Ultrafast appears only
  when the upstream catalog offers it for that account and model.
- **Claude recovery:** reattach live prewarm workers before their first
  transcript exists, and reuse recovered default-account residents instead of
  spawning additional idle workers. Accepted prompts are never replayed.
- **Side-chat cleanup:** retain private identity receipts after deletion so
  late native writes cannot expose closed forks as ordinary sessions. Hide
  catalog entries proven to contain only metadata.
- **Scroll:** clicking the bottom button jumps immediately to the latest message.
- **Proxy routing:** use explicit HTTP proxy environment settings for the Relay,
  retain environment bypass rules and direct loopback connections, and avoid
  automatically selecting unavailable system SOCKS proxies.

### Upgrade

**Protocol v73 is incompatible with v72.** Coordinate every tier in one
maintenance window: stop incompatible old Wrappers, upgrade Relay + Web, then
upgrade and start all Wrappers. For installer-managed deployments, run
`cc-remote update --version 4.0.7 --allow-protocol-change` in an independent
terminal. Device updates verify the paired Relay first and skip its upgrade
when already current. Update other devices individually and reload Web/PWA.
Source and container deployments retain their existing procedures; see the
[installation guide](https://github.com/muggle-stack/cc-remote/blob/v4.0.7/docs/installation_en.md).

The Relay control connection honors `HTTPS_PROXY` / `HTTP_PROXY`, their lowercase
variants and `NO_PROXY` / `no_proxy`. Deployments relying solely on `ALL_PROXY`
or system proxy settings must configure an explicit HTTP proxy endpoint.
Claude/Codex model connections retain their own configuration.

Upgrading from v4.0.6 does not require restarting the independent Claude
session service for these fixes. Older deployments must still follow the
[service migration guide](https://github.com/muggle-stack/cc-remote/blob/v4.0.7/docs/claude-session-service.md)
after native work and pending input drain. Ordinary Wrapper upgrades preserve
the independent service and its tasks.

Release assets contain Web, Relay and Claude/Codex Wrappers. Experimental DSH
and Desktop installers are not included.
