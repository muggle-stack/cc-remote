# cc-remote v4.0.0

## 中文

v4.0.0 集中完善 Claude Code 与 Codex 的会话连续性、历史、侧聊、文件预览和移动端
体验，并新增终端工作台预览版。产品版本为 **4.0.0**，通信协议为 **v72**。

### 功能与修复

- **Claude 会话连续性**：可选独立会话服务保留原生任务，Wrapper 重连恢复已接受的
  消息和待回答问题；支持运行中原生引导、思考摘要和后台任务续跑。
- **后台任务与历史**：主回复结束后仍运行的子任务不会阻塞下一条普通消息；子任务
  回归时按原生边界合并内容。修复持续 running、空的“已处理”、排队提示词遗漏、
  手动压缩重复，以及大图片导致会话工作目录无法识别的问题。
- **上下文与用量**：会话级上下文控制、压缩状态与最近请求用量；处理指示旁显示
  原生输入/输出 token，点按可查看完整数字与缓存用量。
- **历史与差异**：分页摘要和按需过程详情保留阅读位置；每轮文件差异独立归档，
  标明证据缺失或截断，后续工作区修改不会改写旧轮差异。
- **侧聊与预览**：可恢复的多侧聊、附件和独立控制；会话文件浏览与静态页面预览，
  以及音频、PDF、表格、Markdown 和 Mermaid 等内容预览。
- **阅读与手机体验**：低饱和主题、整体字体加粗、紧凑后台任务入口；修复 iOS
  流式输出抢滚动、键盘打开时抖动，以及键盘提示粘贴导致文字或附件重复的问题。
- **终端工作台（预览）**：通过相同 Relay/Wrapper 使用 Claude/Codex 的 Code/Work，
  提供会话树、标签、Vim 编辑、排队、工具详情和文件预览；需按终端指南从源码安装
  可选 TUI 依赖。

本次发布范围为 Claude/Codex。DSH、Electron 客户端和托管浏览器/MCP computer use
实验功能保留在各自开发分支。静态文件/页面预览仍包含在本次发布中。

### 从 v3 升级

- v3.0.0 使用协议 v20，本版使用 v72。**Relay、Wrapper、Web 与 TUI 必须协调升级**，
  不能混用旧客户端；升级后重新加载浏览器/PWA。
- 按部署文档先完成 staging 和校验，保留外部配置、设备授权、账号及会话私有状态；
  使用不可变发布与配套状态快照进行激活和回滚。
- Claude 使用已登录的日常 CLI，要求 **Claude Code ≥ 2.1.263**；已验证的
  **Claude Agent SDK 固定为 0.2.151**。独立 Claude 服务有自己的生命周期，
  不能通过普通 Wrapper 重启升级仍在运行的原生任务；服务升级须按文档等待排空。
- Codex Code 继续使用官方 app-server。原生 CLI 与 Wrapper 应连接同账号 daemon；
  Codex App 共享接入仍是单独可选配置。

## English

v4.0.0 improves session continuity, history, side chats, file previews and mobile
interaction for Claude Code and Codex, and adds a terminal workspace preview.
The product version is **4.0.0** and the wire protocol is **v72**.

### Highlights

- **Claude continuity:** an optional independent session service preserves native
  work across Wrapper reconnects, recovering accepted inputs and pending
  questions. Native steering, thinking summaries and background continuations
  retain their original message ownership.
- **Background work and history:** running children no longer block the next
  normal prompt after the main response ends. Native task returns keep the
  correct timeline. Fix stuck running states, empty process disclosures, omitted
  queued prompts, duplicate manual compaction and cwd recovery after large images.
- **Context and usage:** per-session context controls, compaction state, recent
  request usage and native input/output token counters, with exact counts and
  cache usage available on click or tap.
- **History and diffs:** paged summaries and on-demand details preserve reading
  position. Archived per-turn file changes retain their original evidence and
  explicitly identify missing or truncated patches.
- **Side chats and previews:** recoverable multiple side chats, attachments and
  independent controls; session file browsing and static page previews, including
  audio, PDF, spreadsheets, Markdown and Mermaid.
- **Readability and mobile:** muted themes, a global bold-text preference and
  compact background task controls. Live output yields to user scrolling and
  keyboard changes; duplicate iOS keyboard paste deliveries are suppressed.
- **Terminal workspace preview:** session trees, tabs, Vim editing, queue controls,
  tool details and file previews for Claude/Codex Code/Work over the same relay.
  Follow the terminal guide to install the optional TUI dependencies from source.

This release contains Claude/Codex. DSH, Electron and managed-browser/MCP computer
use experiments remain on separate development branches. Static file and page
previews are included.

### Upgrade from v3

- v3.0.0 used protocol v20; this release uses v72. **Upgrade Relay, Wrapper, Web
  and TUI together**, then reload browser/PWA clients. Mixed versions are rejected.
- Stage and validate before activation. Preserve external configuration,
  device authority and private account/session state; use immutable releases
  with matching state snapshots for activation and rollback.
- Claude requires the signed-in daily **Claude Code CLI ≥ 2.1.263**, with the
  verified **Claude Agent SDK pinned to 0.2.151**. The independent service must
  drain before its own upgrade; an ordinary Wrapper restart does not upgrade
  active native sessions.
- Codex Code uses the official app-server. Daily CLI and Wrapper connections
  should share the same account's daemon. Codex App attachment remains optional.
