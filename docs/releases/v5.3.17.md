# cc-remote v5.3.17

## 中文

修复更新后的会话恢复，并将全局警告收进顶部状态栏。

- 修复应用内更新或重连后，后台 Work 会话的查询被误当成 Code 会话切换，出现「当前操作不适用于这个会话」的问题。后台查询和历史读取重试不再触发切换，自动恢复保留明确的引擎和 Work／Code 归属。
- 当前文件差异、文件预览等依赖已恢复会话的读取，先恢复当前查看的会话再重试，避免 Wrapper 重启后窗口停在「会话未启动」的错误上。
- 全局操作警告、会话通知、版本差异及持续的 DSH 连接异常统一收进顶部状态栏。点击可查看原因，保留更新和刷新页面入口，失败提示可手动确认，连接类提示随恢复状态变化。
- 消息发送失败和待回答问题继续显示在对应位置；Codex 原生诊断仍保留在状态详情中。

通信协议保持 **v90**，Claude Agent SDK 保持 **0.2.174**。本次更新不更换原生引擎版本。

已启用应用内更新的设备，可从右上角「⋮ → 检查更新」进入并安装。也可使用：

```sh
cc-remote update --check --version 5.3.17
cc-remote update --version 5.3.17
```

首次启用条件见[应用内更新说明](https://github.com/muggle-stack/cc-remote/blob/v5.3.17/docs/in-app-updates.md)。设备需要能够访问 GitHub；已知代理 TLS 失败仍可能被显示为「协议变化」，本次未调整该错误分类。

## English

Fix session recovery after updates and consolidate global warnings in the header.

- Fix background Work reads being preceded by a default Code switch after an in-app update or reconnect, causing an unrelated operation-not-applicable warning. Background and historical reads no longer trigger switches; recovery retains the known engine and Work/Code route.
- Restore the focused session before replaying current-file diffs, file previews and other reads requiring a resident context, preventing open panels from being left with a session-not-running error after a Wrapper restart.
- Move global command warnings, conversation notices, version differences and prolonged DSH connection errors into the header status entry. Details, update actions and page refresh remain accessible; failures can be acknowledged and connection feedback follows recovery.
- Keep message-send failures and pending questions in their existing locations. Native Codex diagnostics remain in the status sheet.

Wire protocol **v90** and Claude Agent SDK **0.2.174** are unchanged. This release does not upgrade native engines.

On devices with in-app updates enabled, open **⋮ → Check for updates** to install, or run:

```sh
cc-remote update --check --version 5.3.17
cc-remote update --version 5.3.17
```

See the [in-app update guide](https://github.com/muggle-stack/cc-remote/blob/v5.3.17/docs/in-app-updates.md) for first-time setup. Devices need GitHub connectivity; the existing misclassification of some proxy TLS failures as a protocol change remains unchanged.
