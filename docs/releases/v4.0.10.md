# cc-remote v4.0.10

## 中文

v4.0.10 补齐 Linux 安装的更新器入口，并在升级后按依赖检查清理旧版本备份。
产品版本 **4.0.10**，通信协议保持 **v74**，Claude Agent SDK 保持 **0.2.157**。

### 本次更新

- **统一更新入口**：支持将符合条件的旧 Linux 不可变安装迁入标准更新器，
  注册 `cc-remote` 命令和安装信息，保留登录、配对、账号及代理配置。
- **Supervisor 支持**：已有 Supervisor 管理的 Linux Wrapper（包括容器）可显式安装或
  接管，绑定实际目录、用户、HOME 和配置。兼容较旧的 Supervisor 接口；更新仅操作
  指定 Wrapper，不重启独立 Claude 会话服务或其他程序。
- **备份保留**：切换前记录代码、配置和私有状态回滚资料；验收后保留当前版本、
  上一版完整回滚资料及仍被引用的运行依赖，清理有记录且确认不再使用的更早版本。
  同版本更新可重新验活后重试清理，`--check` 始终只读。
- **失败恢复**：修复 Supervisor 首次安装失败后残留进程组导致无法重试的问题，
  以及 Relay 配置备份失败时误删已登记待激活版本的问题。
- **清理保护**：检查 systemd 服务目录、环境文件、可执行文件别名和依赖链，
  删除前再次检查，防止遗漏停止中的服务或清理期间新增的引用。

**清理范围**：未知历史备份、来源不明的目录和仍在使用的文件不会自动删除。
服务通过 shell 命令、Python 模块等间接启动而无法确定依赖时，会暂停自动清理并
保留更多旧版本，需人工核对清理清单；升级成功不代表所有旧备份都已删除。

### 升级

从 v4.0.9 升级时协议不变。安装器管理的部署在独立终端运行：

```bash
cc-remote update --check
cc-remote update --version 4.0.10
```

设备更新先核对配对 Relay，必要时先升级 Relay + Web；已是目标兼容版本时只更新本机。
其他设备各自更新。没有 `cc-remote` 命令的旧 Linux 安装或 Supervisor 部署，需先按
[安装与升级](https://github.com/muggle-stack/cc-remote/blob/v4.0.10/docs/installation.md)
完成一次显式迁移／接管。源码部署与镜像重建不会自动接管。
用户安装使用预构建产物，不需要运行 CI、pytest 或前端构建。

发布包包含 Linux Relay、Linux/macOS Wrapper 的 x86_64 与 arm64 版本，Relay 内含 Web。
Desktop 和实验 DSH 安装包不在本次 Release 中；不要求重启独立 Claude 会话服务。

## English

v4.0.10 brings legacy Linux installations into the updater and adds dependency-aware
retention after managed upgrades. Product version **4.0.10**, wire protocol **v74**,
Claude Agent SDK **0.2.157**.

- Register the management CLI and installation metadata when explicitly migrating
  eligible immutable Linux installations, preserving native login, pairing and
  external account/proxy configuration.
- Install or adopt Wrappers through an existing Supervisor, including Linux
  containers. Bind the actual root, user, HOME and configuration, support older
  Supervisor interfaces, and change only the selected program.
- Record recovery sets before activation. After acceptance, retain the active
  release, one complete previous rollback and all referenced runtime dependencies.
  Same-version updates retry verified cleanup; `--check` remains read-only.
- Remove fresh Supervisor groups on failed-install rollback so retries work, and
  preserve prepared Relay releases when configuration backup fails.
- Discover dormant service definitions, environment files, executable aliases and
  dependency chains. Revalidate immediately before removal and preserve files when
  references change or discovery is incomplete.

**Retention limits:** unknown backups, unregistered directories and referenced
files remain untouched. Unresolved indirect service commands, including shell
strings and Python module invocations, defer automatic deletion and require an
explicitly reviewed inventory. A successful upgrade can retain additional old
versions.

### Upgrade

The protocol is unchanged from v4.0.9. In an independent terminal, use
`cc-remote update --check`, then `cc-remote update --version 4.0.10` for managed
installations. Each device verifies its paired Relay first, updates Relay + Web
when needed, and skips that step when already compatible and current. Update other
devices separately. Existing unregistered Linux/Supervisor installations need one
explicit migration/adoption through the
[installation guide](https://github.com/muggle-stack/cc-remote/blob/v4.0.10/docs/installation_en.md).
Source checkouts and image rebuilds are not automatically adopted. Users install
prebuilt artifacts without running CI, pytest or frontend builds.

Assets include Linux Relay and Linux/macOS Wrapper packages for x86_64 and arm64,
with Web bundled in Relay. Desktop and experimental DSH installers are not included.
The independent Claude session service does not need to be restarted.
