# cc-remote v5.3.34

## 中文

本次更新修复会话已经空闲时，应用更新仍停留在“等待安全更新”的问题。

- Codex 重复确认输入身份或从历史回填时，已经持久化的记录会正确完成核对并清除待处理状态。
- 轮次结束并释放所有权后，继续核对同一运行代次中已经接纳的身份证明。
- 持久化失败、身份冲突或运行代次失配时保留待处理记录。
- 安装前等待 Wrapper 控制连接恢复的时间从 15 秒延长到 120 秒，更新仍可取消，超时仍会退出。

发布通信协议为 **v94**，Claude Agent SDK 版本为 **0.2.174**。Relay 与 Web 配套升级，Wrapper 通过独立维护通道逐台升级。

修复随新版 Wrapper 生效。旧版已保留阻塞状态时，可先重启 Wrapper，再重试更新。

```sh
cc-remote update --check --version 5.3.34
cc-remote update --version 5.3.34
```

查看安装与升级步骤。[安装说明](https://github.com/muggle-stack/cc-remote/blob/v5.3.34/docs/installation.md)

## English

This update fixes application updates remaining in the safe-update wait after Codex sessions become idle.

- Settle pending Codex input identities when duplicate confirmations or history backfill find an already durable matching record.
- Retry identity proofs accepted by the same runtime generation after turn ownership has been released.
- Retain pending identities when persistence fails, identities conflict, or runtime generations differ.
- Extend the pre-activation Wrapper control recovery window from 15 to 120 seconds, retaining cancellation and timeout checks.

Wire protocol is **v94**. Claude Agent SDK version is **0.2.174**. Upgrade Relay and Web together, then upgrade Wrappers individually through maintenance.

The fix takes effect in the new Wrapper. If an older Wrapper already holds stale blocking state, restart that Wrapper and retry the update.

The commands above select this release explicitly. Follow the installation guide for setup and upgrades. [Installation guide](https://github.com/muggle-stack/cc-remote/blob/v5.3.34/docs/installation_en.md)
