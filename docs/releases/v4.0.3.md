# cc-remote v4.0.3

## 中文

v4.0.3 修复 Claude 历史对话重复、后续问题被放到第一条问候之前的问题。
产品版本 **4.0.3**，通信协议保持 **v72**。

### 本次修复

- 浏览历史和读取缓存时，按原生用户消息及其唯一浏览器别名合并同一条消息，
  避免翻页、重连或重新加载后出现两份对话和顺序错乱。
- 保留已展开的思考／工具过程和正确的详情查询标识；历史副本不会改写较新记录
  的运行、完成或错误状态。
- 同文但身份不同的真实消息仍分别保留，不使用文字、时间戳或共享任务 ID 去重。

### 升级

在独立终端执行 `cc-remote update`；Linux 的系统级安装使用
`sudo cc-remote update`。更新会先检查配对的 VPS；其他设备各自更新时，
已是目标版本的 VPS 会跳过。更新后重新加载网页或 PWA，让浏览器使用新的历史合并逻辑。
本次修复不修改原生 Claude JSONL，也不需要删除会话或手工清空历史。

v4.0.0 用户按[安装与升级](https://github.com/muggle-stack/cc-remote/blob/v4.0.3/docs/installation.md)
完成一次安装器升级，再使用更新命令。旧 Release 保留不变。

## English

v4.0.3 fixes duplicated Claude conversations and later prompts appearing before
the initial greeting while browsing history. Product version **4.0.3**, wire protocol **v72**.

- Reconcile native user-message identities and their unique browser aliases across
  loaded and cached history pages, preventing duplicate copies and misplaced rows.
- Preserve expanded process details and native detail lookup IDs. Older history
  copies cannot override the newer copy's running, completed or error state.
- Keep genuinely distinct messages even when their text matches; matching prose,
  timestamps and shared task IDs are not used as deduplication keys.

Run `cc-remote update` in an independent terminal (`sudo cc-remote update` for
system-wide Linux installs). The updater checks the paired Relay first and skips
it if already at the target version. Update other devices individually, then
reload Web/PWA to load the new history merge logic. Native Claude JSONL files are
unchanged; deleting sessions or manually clearing history is unnecessary.

v4.0.0 requires a one-time [installer upgrade](https://github.com/muggle-stack/cc-remote/blob/v4.0.3/docs/installation_en.md)
before the update command is available. Existing releases remain available.
