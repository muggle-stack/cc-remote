# cc-remote v4.0.5

## 中文

v4.0.5 改善 Claude 消息与控制指令的响应，修复停止恢复、Codex Shared 启动及
子代理状态反馈。产品版本 **4.0.5**，通信协议保持 **v72**，Claude Agent SDK
保持 **0.2.157**。

### 本次修复

- **Claude 控制响应**：慢会话启动、CLI 预检和上下文读取不再阻塞无关会话的消息、
  停止指令与心跳。同一会话的启动、发送与停止仍保持顺序；指令队列有数量和字节
  上限，重连重试保留可靠回执。
- **Relay 转发**：不同设备独立发送；卡住的浏览器连接在转发路径之外限时清理，
  避免一个慢连接拖住其他浏览器的后续消息。
- **Claude 停止恢复**：消除托管回合与后台恢复同时重连的竞争，后台交接沿用原有
  停止期限。界面区分“停止确认超时”和原生确认的“已打断”。
- **Codex Shared**：启动器和 App 发现使用与 Wrapper 一致的原生套接字校验，
  支持受保护的套接字别名，修复共享服务已启动却提示未就绪的问题。继续校验
  账号归属、私有权限和监听器身份。
- **BTW 与子代理**：Claude Code 侧聊启动时继承父会话的模型选择，避免持续显示“模型读取中”；
  关闭的设置面板不再阻断 `/` 聚焦主输入框。Codex 和 Claude 子代理都显示动态
  小火花，各子代理的处理过程可以独立展开或收起。

### 升级

从 v4.0.4 升级可在独立终端运行 `cc-remote update`；Linux 系统级安装使用
`sudo cc-remote update`。更新后重新加载网页或 PWA。

启用了独立 Claude 服务时，普通 Wrapper 更新会保留原服务和正在执行的任务。
本次服务端的并行启动修复需要更新该独立服务进程才能生效；按
[Claude 服务指南](https://github.com/muggle-stack/cc-remote/blob/v4.0.5/docs/claude-session-service.md)
等待原生任务、回调及后台工作结束后完成服务更新，保留旧发布和私有状态。
不要为应用此修复重启仍在工作的服务。

从 v4.0.3 或更早版本升级，需遵循
[v4.0.4 的 SDK 升级要求](https://github.com/muggle-stack/cc-remote/blob/v4.0.5/docs/releases/v4.0.4.md#升级)，
通过[安装与升级](https://github.com/muggle-stack/cc-remote/blob/v4.0.5/docs/installation.md)
使用 v4.0.5 安装包完成迁移。

本次发布 Web、Relay 和 Claude/Codex Wrapper；通信协议和模型账号配置保持兼容。

## English

v4.0.5 improves Claude message and command responsiveness and fixes Stop recovery,
Codex Shared launch, and subagent activity feedback. Product version **4.0.5**,
wire protocol **v72**, Claude Agent SDK **0.2.157**.

- **Claude responsiveness:** slow session startup, CLI preflight and context reads
  no longer block unrelated sessions' messages, interrupts or heartbeats. Preserve
  per-session ordering, bounded command intake and reliable retry receipts.
- **Relay forwarding:** isolate device sends and clean up stalled browser
  connections outside the forwarding path, with a bounded close deadline.
- **Stop recovery:** prevent managed-turn and background recovery from reconnecting
  the same Claude session twice. Keep the original stop deadline across handoff
  and distinguish a timeout from a confirmed native interruption.
- **Codex Shared:** use the Wrapper's protected native socket-alias validation in
  the launcher and App discovery, retaining account, ownership, permission and
  listener-identity checks.
- **BTW and subagents:** initialize a Claude Code side chat's model from its parent, let `/`
  focus the main composer when BTW settings are closed, restore the animated
  working sparkle for both engines, and allow each agent's process to expand or
  collapse independently.

### Upgrade

From v4.0.4, run `cc-remote update` in an independent terminal
(`sudo cc-remote update` for system-wide Linux installations), then reload Web/PWA.

An ordinary Wrapper update preserves an existing independent Claude service and
its active tasks. The concurrent-startup fix requires updating that service
process separately. Follow the
[Claude service guide](https://github.com/muggle-stack/cc-remote/blob/v4.0.5/docs/claude-session-service.md)
after native turns, callbacks and background work have drained; retain the old
release and private state. Do not restart a busy service to apply this fix.

Upgrades from v4.0.3 or earlier must follow the
[v4.0.4 SDK migration requirements](https://github.com/muggle-stack/cc-remote/blob/v4.0.5/docs/releases/v4.0.4.md#upgrade)
and use the v4.0.5 installer as described in the
[installation guide](https://github.com/muggle-stack/cc-remote/blob/v4.0.5/docs/installation_en.md).

This release contains Web, Relay and Claude/Codex Wrappers. The wire protocol
and model-account configuration remain compatible.
