# cc-remote v5.3.15

## 中文

加入经管理员启用的应用内更新，并修复 Claude 继续处理详情和旧版本清理。

- 右上角「⋮ → 检查更新」显示页面、服务器、当前设备的版本、稳定版更新说明和安装进度。「加粗字体」移至「外观 → 阅读设置」。
- 设备管理员一次性执行 `cc-remote ui-updates enable` 后，可在页面发起更新。更新等待会话、权限问答、后台任务和排队消息完成；安装任务由系统独立运行，关闭页面不会中断。
- 已有管理员 SSH 入口的设备可通过 `cc-remote ui-updates enable --allow-relay-update` 允许同时更新配对 Relay。其他设备各自更新；浏览器不接收 sudo 密码。
- Relay 提交后遇到 SSH 断线、状态查询失败或健康检查未通过时，保留「结果待确认」及原任务编号，避免重复安装。刷新页面仍保护草稿、附件和未保存编辑。
- 修复 Claude 等待问题回答期间收到后台任务或子代理返回后，继续处理的工具／思考详情可能合并到错误轮次、暂时显示加载失败的问题。
- 清理器识别 Chromium 的 Singleton 标记，避免将其误判为失效的文件依赖；继续保留实际使用中的版本及无法确认用途的目录。

通信协议保持 **v90**，Claude Agent SDK 保持 **0.2.174**。本次 cc-remote 更新不会替换或重启原生 DSH、Codex 或独立 Claude 会话服务。

首次接入应用内更新，需要先用既有部署流程升级 Relay/Web 和设备，再执行一次性启用：

```sh
cc-remote update --check --version 5.3.15
cc-remote update --version 5.3.15
cc-remote ui-updates enable
```

已部署包含更新入口的源码版本可直接用页面测试本次正式版更新。设备需要能够访问 GitHub；已知代理 TLS 失败目前可能被显示为「协议变化」，需核实代理连接。详细说明见[应用内更新](https://github.com/muggle-stack/cc-remote/blob/v5.3.15/docs/in-app-updates.md)。

发布继续包含鸿蒙 **0.1.0-preview.6** 未签名 HAP、构建元数据和独立校验文件，沿用已验证的原生构建；已安装 preview.6 无需重装。HAP 需要使用自己的开发者及设备 Profile 签名。本次没有新的 Desktop 安装包。

## English

Add administrator-enabled in-app updates and fix Claude continuation details and release retention.

- Open **⋮ → Check for updates** to view page, server and current-device versions, stable release notes and installation progress. Bold text moves to **Appearance → Reading settings**.
- After an administrator runs `cc-remote ui-updates enable`, updates can be started from the page. Installation waits for sessions, permission questions, background tasks and queued messages, then runs as an independent OS job that survives closing the page.
- Devices with an existing administrator SSH route can authorize paired Relay updates with `cc-remote ui-updates enable --allow-relay-update`. Update other devices individually; the browser never accepts sudo passwords.
- Preserve an unresolved result and the original job identity after uncertain Relay submission, status reads or health checks, preventing duplicate installations. Page refresh continues to protect drafts, attachments and unsaved edits.
- Fix Claude tool/reasoning details being assigned to the wrong continuation or temporarily failing to load when a background task or subagent returns while a question is awaiting an answer.
- Recognize Chromium Singleton markers during retention instead of treating them as broken file dependencies. Continue preserving live runtime dependencies and directories whose use cannot be established.

Wire protocol **v90** and Claude Agent SDK **0.2.174** are unchanged. Updating cc-remote does not replace or restart native DSH, Codex or the independent Claude session service.

For first-time setup, upgrade Relay/Web and the device through the existing deployment workflow, then enable UI updates:

```sh
cc-remote update --check --version 5.3.15
cc-remote update --version 5.3.15
cc-remote ui-updates enable
```

Source installations already running the managed in-app update feature can test this release from the page. The device needs GitHub connectivity; a known limitation can mislabel proxy TLS failures as a protocol change. Verify the proxy connection in that case. See the [in-app update guide](https://github.com/muggle-stack/cc-remote/blob/v5.3.15/docs/in-app-updates.md).

Assets retain the verified HarmonyOS **0.1.0-preview.6** unsigned HAP, native-build metadata and separate checksums. Existing preview.6 users need no native reinstall; the HAP requires your own developer/device signing profile. No new Desktop installer is included.
