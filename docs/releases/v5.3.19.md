# cc-remote v5.3.19

## 中文

修复应用内更新提交后未收到确认，窗口一直停在「正在确认原更新结果」的问题。

- 页面自动按原请求编号查询设备记录，包括已经不在最新任务位置的历史记录。查到后恢复进度，暂未查到时显示「更新尚未启动」并提供重试；查询本身不会启动安装。
- 重试和刷新继续使用原请求编号，避免延迟到达的首次提交与重试重复安装。结果无法确认时保留原请求，不把读取失败当成未启动。
- 提交失败的原因不再被普通状态轮询清掉，刷新后仍可查看；延迟响应或错误归属的记录不会覆盖已确认的更新状态。
- 更新窗口区分「更新请求待确认」和「更新尚未启动」，分别提供确认或重试操作。旧设备不支持按编号查询时，保留沿用原请求的手动重试入口。

沿用 v5.3.18 的更新准入规则：确认独立运行且可恢复的任务可以继续；Wrapper 内的排队消息、私有任务、临时附件依赖、Codex／DSH 待回答问题等仍需等待安全边界。

通信协议保持 **v90**，Claude Agent SDK 保持 **0.2.174**。本次更新不更换原生引擎版本。

已启用应用内更新的设备，可从右上角「⋮ → 检查更新」进入并安装。也可使用：

```sh
cc-remote update --check --version 5.3.19
cc-remote update --version 5.3.19
```

首次启用条件见[应用内更新说明](https://github.com/muggle-stack/cc-remote/blob/v5.3.19/docs/in-app-updates.md)。设备需要能够访问 GitHub；已知代理 TLS 失败仍可能被显示为「协议变化」，本次未调整该错误分类。协议或 SDK／服务契约变化仍需协调维护。

## English

Recover in-app updates after a lost submission acknowledgement instead of leaving the dialog stuck confirming the previous request.

- Automatically look up the original request on the device, including historical receipts that are no longer the latest job. Restore recorded progress or offer a retry when no receipt is found; lookup never starts an installer.
- Preserve the original request identity across retries and reloads so a delayed first submission cannot launch a duplicate installation. Keep uncertain requests rather than interpreting read failures as absence.
- Retain submission errors through successful status polls and reloads. Ignore stale responses and receipts belonging to another request or version.
- Distinguish an unconfirmed request from an update that has not started, with the corresponding confirmation or retry action. Older devices retain an explicit same-request retry fallback.

The v5.3.18 admission rules still apply: independently owned, recoverable tasks can continue; Wrapper-owned queues, private tasks, temporary attachments, pending Codex/DSH questions and other affected operations still require a safe boundary.

Wire protocol **v90** and Claude Agent SDK **0.2.174** are unchanged. This release does not upgrade native engines.

On devices with in-app updates enabled, open **⋮ → Check for updates** to install, or run:

```sh
cc-remote update --check --version 5.3.19
cc-remote update --version 5.3.19
```

See the [in-app update guide](https://github.com/muggle-stack/cc-remote/blob/v5.3.19/docs/in-app-updates.md) for first-time setup. Devices need GitHub connectivity; the existing misclassification of some proxy TLS failures as a protocol change remains unchanged. Protocol or SDK/service-contract changes still require coordinated maintenance.
